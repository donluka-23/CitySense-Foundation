# Ideas, changes and founder approvals

Use the [CR template](CR-TEMPLATE.md). Chief assigns CR-0001 onward when an actual change is requested.
An idea begins as IDEA_INBOX; triage describes value, affected decision IDs, uncertainties and November impact.
A roadmap proposal or founder question is not a completed approval record.

Lifecycle: IDEA_INBOX → TRIAGED → CR_DRAFT → FOUNDER_APPROVED → CONTRACT_READY → TASK_READY
→ IN_PROGRESS → INTEGRATION_REVIEW → QA → HUMAN_ACCEPTED.
Track blockers separately. The bootstrap's three tickets remain PROPOSED / CR_DRAFT.

Founder approves material product/science, commercial ordering, privacy, providers, payments and scope.
Approval records must quote or accurately reference the dated instruction, scope, decision IDs, chosen option,
affected contract/version and conditions. Do not invent signatures or promote PROPOSED clauses.
Chief integrates approved amendments through additive ADRs/versioned contracts; preserves old receipts.
Emergency findings can be triaged immediately; all edits still require session authorization.

New services (eSIM, drivers, tours, contacts, external agents) also require a capability card:
market/provider/category/location model; allowed reads/actions; price/availability authority and freshness;
data/publication/redistribution/archival rights; consent and recipients; legal/rights owner;
client scopes; SLA or unknown; tests; approval/revocation status. Unknown entries block activation.

## Approved v1.2 stage control

[STAGE_GATES](../STAGE_GATES.md) and [FOUNDER_APPROVALS](../FOUNDER_APPROVALS.md) apply to every CR.
Use CR-###, blueprint IDs, user impact, affected modules/contracts, scope/time/risk, alternatives and proposed stage.
Founder owns tradeoffs and exact stage/artifact/scope approval; append the actual decision/provenance.
A new idea remains intake, never automatic implementation or November scope. Revisions identify their artifact;
scope increase requires fresh approval. Emergency triage does not authorize unrelated changes.
