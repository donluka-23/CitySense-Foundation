## Precedence by domain

1. Current user instructions delimit authorized actions. Bootstrap scope is governance/configuration only.
2. Founder-approved DECIDED clauses control product intent. Only explicit founder decisions supersede them.
3. Accepted ADRs, executable API/schema semantics and protected research contracts remain binding in their technical/scientific domains.
4. A material conflict blocks the affected contract change until a dated founder-approved CR/ADR resolves it.
   No document wins by silently overriding another; safe unrelated additive documentation may proceed.
5. Code establishes actual behavior; tests and dated receipts establish only the environment/checks they executed.
   Missing implementation or a code/contract mismatch is reported; code alone cannot authorize a new product decision.
6. Governance/backlog/RFC proposals plan future work; they do not prove implementation, permissions or validity.
   Historical plans/receipts remain preserved; current dated status overlays distinguish stale facts.

PROPOSED is not DECIDED. TO VERIFY is feasibility/rights uncertainty; TO VALIDATE is an empirical hypothesis.
DEFERRED does not mean rejected. DECIDED is not IMPLEMENTED; TESTED is not PILOT_VERIFIED.
No numeric commercial equivalence, accuracy, participant count or success threshold has been approved.
